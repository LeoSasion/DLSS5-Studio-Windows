一、开始使用

1. 将完整 ZIP 解压到可写文件夹，例如 D:\Apps\DLSS Studio。
2. 双击“DLSS Studio.exe”，或运行“启动工作台.bat”。不要直接在压缩包内运行，不要单独移动 EXE。
3. 上传图片或视频，选择尺寸、风格和强度，点击“开始处理”。输出尺寸保持素材比例。

Python、依赖、FFmpeg 和处理引擎已内置，无需管理员权限，不需要另装 Python 或 pip。独立窗口使用 Microsoft WebView2；未安装时会询问是否通过包内微软引导组件安装，首次安装此组件需要联网。

支持 Windows 10/11 x64，窗口使用 .NET Framework 4.6.2 或更高版本。神经渲染需要兼容的 NVIDIA 显卡与驱动；此包不安装或修改驱动。2026-10-26曾在RTX PRO 6000 Blackwell、591.86驱动上验证旧310.8运行库；本次310.9.16.0仅完成文件身份核对及引擎编译，按更新要求未运行测试或GPU处理，591.86是否能运行新版尚待人工反馈。新版可能需要更高驱动。NVIDIA初版DLSS 5产品使用616.64、RTX Remix 1.6.1使用616.92作为产品基线，二者都不是已核实的该DLL精确最低要求。RTX 30/40仍需对应实体卡反馈，不能据此承诺全部显卡或官方支持范围。

本包RTX 30/40共用ShortFuse / OpenNR社区兼容库，RTX 50使用NVIDIA原版，均为310.9.16.0。默认采用较轻量的NR网络Preset B（值2），原有默认/自然/电影外观风格与参数含义保持不变。网络B与外观风格是独立设置，不新增选择界面；本次没有测量画质、速度或显存变化。

二、窗口、预览和参数版本

右上角可最小化、最大化/还原、关闭及打开外部浏览器；拖动顶部空白处移动窗口。默认服务地址为 http://127.0.0.1:7860/，端口占用时自动选择其他可用端口，“浏览器”按钮打开实际地址。外部浏览器使用期间请保持独立窗口开启，可将它最小化。二者各自保存当前工作台，共用处理服务和最近结果。

普通窗口开启“玻璃”时，面板背景实时模糊，间隙保持透明；最大化时强制关闭玻璃，按主题使用不透明黑底或白底，还原后恢复原偏好。深浅主题、缩放、对比和设置面板均适配小窗口。

预览支持原画、增强后、拖动对比、适应窗口、100%、滚轮缩放与空格拖动平移。视频的100%指当前预览像素尺寸；浏览器预览可能低于下载成片，不宜只用小预览判断4K细节。

“差分”显示浏览器中增强与原画的显示差异，相同区域接近黑色；会受预览压缩、缩放、色彩映射和显示环境影响，不是原始HDR或无损误差测量。

修改设置后，预览和下载仍对应已经生成的版本，界面提示“设置待应用”；再次处理后产生新版本。强度保持0–200%，色彩融合0–100%。可用“我的设置”保存参数，在“最近结果”中命名版本、标记满意和复用设置。清除浏览器或desktop-profile数据会清除对应自定义设置。

视频通过起止游标选择片段，默认整段；移动播放游标不改变导出范围。端点方向键逐帧、Shift加方向键一秒、Home/End移至允许边界。终点不包含在导出片段内。暂停、拖动定位后，原片与结果按实际源PTS帧映射对齐，考虑可变帧率和片段实际起点；Alt加左右方向键按帧步进。映射不可用时退回媒体时间对齐，播放中的校正不承诺每个刷新瞬间严格同帧。

三、保护、稳定和推理精度

高级设置中的“原画保护区域”可拖出一个固定矩形，内部保留原画，边缘平滑过渡；适合字幕、标识、界面或不希望改动的区域。Escape取消绘制，“清除”移除矩形。它不会自动跟踪移动人物。

肤色保护和高光保护默认0%，用于减少对应区域的增强改动。肤色保护依据颜色判断，不是人脸检测，且与原有“皮肤细节”模型参数不同。

视频“运动与时序”中的时序稳定默认0%，只稳定增强相对原画的改变量，运动不可靠、遮挡或切镜头时降低复用或重置。过强可能降低变化响应，不是相机防抖，也不保证消除所有闪烁。

推理精度默认完整，可选75%或50%快速预览。它缩小模型工作尺寸，再将增强差值回加原尺寸，不改变导出尺寸，但模型细节可能减少。最终判断建议使用完整精度。恢复默认也会重置这些新增控制。

四、串行队列、批量和接续

主增强任务串行运行，最多64个等待任务。“批量添加”按当时的设置逐个上传同类素材并加入整段处理队列；最近结果中可查看每个任务。已加入项目不会因后续某项失败而撤回。临时断网会用同一请求标识确认，刷新也会恢复对已上传待确认项的确认，避免重复入队。

等待任务可以立即暂停或取消。正在处理的视频会在当前片段完成并提交后暂停，界面先显示保存暂停点，再显示已暂停。点击“继续”只补未完成段；图片运行中不支持暂停，可以取消。

关闭独立窗口会停止服务，关闭提示仍可能使用“中断”字样。未完成视频的已提交片段会保留；重开后在最近结果中继续。未提交的当前片段可能重算；等待任务重开后恢复排队，手动暂停项仍等待继续。图片中断或旧版本没有接续信息的记录需要重做。

保留app\uploads、app\ui_out和app\studio-state.json才能接续。素材、模型、驱动或实际处理环境改变时，程序拒绝混用不兼容旧段，请创建新任务。分段使用前置预热和重叠过渡减少接缝，不保证与任意连续模型隐藏历史完全相同。需要之后继续时使用“暂停”，不要用“取消”代替。

五、结果缓存和阶段复用

缓存根据源内容、范围、有效参数、实际模型/驱动/工具身份判断，改名或新建任务不会使相同计算必然重做：
- 设置完全相同：复用成片，不调用模型。
- 视频只改编码、码率、容器等：复用已增强无损段，重新编码/封装。
- 图片只改细节、色彩融合或保护：如模型中间缓存还在，直接重新合成。
- 视频改细节、色彩融合、时序稳定或保护：如原始模型预测缓存还在，可重新合成而不重跑NR；仍可能需要解码和光流。
- 改输出尺寸、风格、模型强度等模型参数、运动、推理精度或实际运行环境：通常重算模型。

原始模型预测按单段预计不超过1 GiB启用，4K长片不保证保留这一层。图片模型中间缓存总预算1 GiB，视频模型预测总预算2 GiB；超预算淘汰可重算的旧中间项。已完成成片和接续用无损段不随这项自动淘汰删除。缓存缺失时自动重算，不降低默认质量。

时间轴标出已处理区间；开始按钮可提示复用机会，最终以实际校验为准。仅改变主题、窗口或预览缩放不影响处理结果。最近结果中的缓存管理先预览释放空间，再清理；默认保留成片，保护当前、满意、活动/暂停任务及使用中的素材。共享文件按最后引用计算可释放空间。勾选清理历史结果前，请先下载需要保留的文件。

六、编码、HDR和媒体信息

视频默认MP4：Windows10选H.264，Windows11选AV1；分别实测各NVENC编码器，不可用时用同格式CPU编码。CPU编码仍需显卡完成增强。推荐码率1080p及以下6 Mbps、1440p 9 Mbps、4K 12 Mbps；可改恒定画质或自定义码率。ProRes、FFV1只显示适用的导出参数。

视频自动识别PQ/HLG和高位深，增强原始帧使用16 bit RGBA，在浮点线性域构造模型代理并回加增强差值。HDR支持BT.709、BT.2020、P3-D65；未知HDR色域明确按BT.2020记录处理，其他已知但未验证色域会提示。视频不需要勾选旧“HDR线性色彩”，该控制只保留在图片中。

HDR导出选择支持的10 bit编码或高精度母版格式。选择H.264时明确转成SDR；高精度增强段仍可用于随后改编码导出HDR。原片和结果的浏览器兼容预览使用一致的SDR BT.709映射，通常限制在1920×1080范围；浏览器预览不等于HDR母版。源预览后台生成，准备中仍可增强；失败可点“重试原片预览”。原始文件保留。

保留适用的静态Mastering Display、MaxCLL/MaxFALL元数据；不沿用原画专属Dolby Vision、HDR10+、HDR Vivid动态映射，不重建动态元数据，不承诺动态HDR保真。静态标签保留不代表完成逐片调色或显示器校准。

默认按源PTS保留可变帧率，按目标容器能力保留多音轨、字幕、章节、附件和适用元数据。音频自动选择能复制则复制，否则重编码。不兼容的媒体流会在日志说明，不能保证任意容器保留所有流；重要素材请检查成片和日志。

七、排查和本机数据

底部状态按钮打开处理日志。“连续视频自检”生成本地运动样片，经过真实队列连续增强，跳过缓存；“复制诊断”包含显卡与组件身份、队列、阶段耗时及复用记录。模型阶段为0且有模型缓存命中帧数，才表示该次未重新计算模型；解码、合成和编码仍可能耗时。

app\uploads\                 上传原片与显示预览
app\ui_out\<任务编号>\       成片、兼容预览、接续片段与缓存
app\studio-state.json         素材/任务索引
desktop-profile\             独立窗口浏览器数据与偏好
logs\desktop-server.log       服务日志

启动失败时确认完整解压、目录可写、WebView2可用，并查看服务日志。处理失败时查看任务日志、磁盘空间和编码器可用性。组件“已匹配”不等于已成功渲染，连续视频自检可核对本次运行。包内不包含制作工作区的历史素材、结果或日志。

八、升级与回退

本次NR更新通过新的完整包提供。将新包解压到独立文件夹，保留旧包；先关闭旧程序，再使用新包。需要迁移历史时一并保留app\uploads、app\ui_out和app\studio-state.json。模型改变会使旧模型缓存和未完成任务的接续信息失效，已有成片可继续保留。

旧版应用增量工具tools\incremental_update.py仍只更新应用代码、界面、渲染程序和桌面启动器，不替换架构模型DLL、Python或FFmpeg，也不覆盖素材、成片、任务索引与desktop-profile。因此旧版应用增量包不能完成这次310.9.16.0模型升级。本次不提供模型增量包。

旧发布包与工作区的310.8文件及组件回退记录保留。为减少体积，新完整包只带当前两份不同的NR DLL（30/40共享一份、50一份），不带旧运行库或其回退历史；需要回到旧运行库时使用保留的旧包。
