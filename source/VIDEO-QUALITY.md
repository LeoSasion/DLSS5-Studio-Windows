# 视频处理优化预览 — 2026-11-05

本轮为独立开发预览。R1/R2 初次开发时按此前要求只进行编译和静态审查；随后 R2 审查修订已完成真实 GPU、桌面 E2E 与回归验证，范围见文末。
短样片功能验证不构成跨显卡兼容性、主观画质或长视频性能保证。

## 已接入

- NVOFA 运动矢量先与“没有运动”的解释比较；静止或匹配无改善的位置输出零运动。关闭猜测的 cost 阈值门控，切镜后同时清除硬件时序提示。LK 回退路径继续可用。
- 普通与高精度视频共用缩略图平移对齐残差、亮度直方图和弱信号防重复触发。缩略图长边上限 64 像素；强信号立即重置，弱信号间隔按源帧率计算。
- 高精度路径改由 GPU 生成 SDR 模型代理、缩小推理输入、提取增强差值、进行时序稳定与原画合成，最后打包 RGBA8/16。原画、代理和差值使用 FP32，模型输入输出保留 NR 所需 FP16。
- 时序稳定使用有界 Catmull–Rom 历史采样，并根据原始画面的局部亮度增益判断历史可信度。保护区域、肤色、高光、PQ/HLG 和支持色域沿用现有含义；强度为零的输出保留主机侧打包路径。
- 不再为普通时序稳定读回运动矢量；不写模型缓存时也不读回整帧浮点 NR 结果。命中模型缓存后仍重新合成；写原始模型缓存所需的读回继续保留。解码、编码和放大路径并非全链路零拷贝。
- 更新流水线身份、原始模型缓存算法版本；本轮产生的结果不混用旧模型中间缓存或旧接续段。原有成片文件继续保留。

切镜阈值与过滤策略仍需人工评价，不能承诺不会误判闪光、快切或快速运动。GPU 后处理增加设备侧历史纹理；与旧 CPU 路径不承诺逐字节一致。默认关闭的时序稳定仍由已有开关控制，未新增工作台选项。

## RTX VSR 的实际状态

已加入共享 NGX 会话的条件编译适配器：仅对 SDR 8-bit 视频放大使用 RTX VSR High（3）；高位深和 HDR 继续原放大路径。不能创建或执行已报告可用的 VSR 时明确失败，不在一段视频中悄悄混用不同放大器。不可用的能力使用 DLSS SR，并写入日志。

**当前预览没有启用 VSR。** 本地缺少 NVIDIA RTX Video SDK；2026-11-05 官方下载链接跳转到 NVIDIA 开发者登录，未取得 SDK 头文件及原版运行库。VSR 条件分支尚未在带 SDK 的构建中编译或运行，不能视为已可用。

从 [NVIDIA 官方页面](https://developer.nvidia.com/rtx-video-sdk/getting-started)取得 RTX Video SDK 1.1 后，指定完整解压根目录构建到空目录：

```powershell
.\app\.venv\Scripts\python.exe -X utf8 -B packaging/build_engine.py --rtx-video-sdk "C:\路径\RTX-Video-SDK" --out source/out-vsr
```

构建入口检查 `include/nvsdk_ngx_helpers_vsr.h`、`bin/Windows/x64/rel/nvngx_vsr.dll` 和 NVIDIA 有效签名，并把运行库放到输出目录。遵守 SDK 自身条款并随分发保留适用许可。VSR DLL 的有无及哈希参与应用缓存身份，实际选择也参与原始模型缓存身份。基础构建不需要 SDK。

## 第二轮开发优化 — 2026-11-05

- 原始尺寸且 `detail=0`、非运动可视化时，直接分块转发原始 RGBA8/16 帧，不初始化 GPU/NGX、不创建模型和光流。每次复制缓冲上限 1 MiB，帧截断和输出错误仍明确失败；编码与媒体封装继续按原有设置执行。日志区分 bypass 和实际推理，不将直接转发记为 NR 验证成功。
- 高精度后处理的提取/稳定、合成和最终读回合并提交，每个 pass 使用独立描述符区域，整批读回后才复用。开启稳定时，这部分原来五次提交等待合为一次；不减少光流等其他阶段的必要同步。新增 GPU 后处理耗时统计。
- 稳定 pass 直接提取本帧增强差值，省去一张 FP32 中间纹理；历史代理通过纹理轮换保留，省去逐帧复制。全尺寸 SDR 直接使用 FP32 原画作代理，再省一张纹理。4K 时每张纹理的像素数据约 126.6 MiB，不含分配对齐开销；实际峰值显存待人工观察。
- 模型缓存直接保存/上传 FP16 字节，去除不必要的 FP16→FP32→FP16 往返。不启用或写失败禁用缓存后，不再计算整帧缓存指纹，也不为缓存读回模型结果。
- 基础打包引擎内嵌六个相关着色器的编译结果，避免视频分段重复编译这些着色器；其它既有着色器仍有运行时编译。源码构建可用 `--runtime-shaders` 保留原来的编译方式。
- 命中模型缓存时不创建只供 NR 推理使用的输入/深度纹理。运动可视化不再创建 NR feature。NR feature 使用作用域释放，后续分配失败时也能清理。
- 像素输出行紧密排列时，直接移交读回缓冲，避免再复制一整帧。带行填充的尺寸仍走逐行去填充。
- `build_package.py --engine-out <编译目录>` 可用新引擎生成独立预览，不必替换正在使用的应用。无 SDK 构建目标中存在 VSR DLL 时，构建预检查先拒绝，避免覆盖引擎后才报错。

第二轮初次开发时只进行基础/源码回退两种引擎编译、着色器编译、Python 语法与文件身份检查；未运行任何渲染、自动化或性能测试。与上一轮的速度、画面及兼容性差异等待人工反馈。VSR 仍未取得官方 SDK，相关分支仍未启用。

## R2 审查修订与 E2E — 2026-11-05

- 修复初始化后约 0.3 秒内真实弱切镜被抑制的问题。初始帧仍重置历史，但不启动真实切镜的防重复窗口；已有强切镜和弱瞬变策略不变。
- 模型中间缓存增加源 FPS 和实际成功初始化的 NVOFA/LK 后端身份，算法版本升至 7，应用流水线身份升至 `studio-render-6-fps-flow-bound-history`。帧率或自动运动后端改变时重新推理，避免误用历史预测。
- NVOFA 初始化失败时先清理已注册资源再回退；析构自动释放资源，fence 值只在注册/执行成功后递增，避免失败清理等待未提交的 fence。
- E2E 发现设置弹窗在滑块变化后重新分页会丢失焦点，现已跳过不改变布局的 range 分页，并在必要分页时恢复原控件与编辑位置。图片/视频共用这一修复，界面不新增选项。脚本 URL 同步更新以失效旧浏览器缓存。

实际环境：NVIDIA RTX PRO 6000 Blackwell Workstation Edition，驱动 591.86，RTX50 原版签名 NR 310.9.16.0，Network B（preset 2）。

已通过：

- 真实图片增强和 48 帧、320×180、24 fps 视频增强；日志确认 48 次实际 NR 推理。导出为 10-bit AV1/MP4，独立检查 48 帧、2 秒与 AAC 音轨。当前环境 NVENC 不可用，工作台自动选择 CPU AV1。
- 完整/75% 推理尺寸、稳定/保护合成、FP16 模型缓存重合成与完整成片缓存。调整色彩时复用 48 帧模型结果、实际 NR 次数为 0；再次完全相同请求返回逐字节相同的视频。
- 原尺寸零细节导出跳过 GPU/NGX，48 帧全部计入 bypass。原始 RGBA8/16 各 3 帧输入输出逐字节一致；截断输入明确失败。编码文件仍受所选编码器影响，不承诺与原压缩视频逐字节一致。
- PQ/HLG 16-bit 原始帧各完成 4 帧真实 NR/FP32 后处理；全画面保护时与原始帧最大误差分别为 1/0 个 16 位量化级。
- 24 fps 模型缓存重放的原始帧 SHA-256 与首次推理相同；改为 60 fps 后重新执行 4 帧推理。NVOFA 与显式 LK 路径均实际执行并正常退出。
- 独立桌面 E2E：上传、渲染、原生下载、当前帧捕获、同步播放、选区偏移、小窗口、4K 横/竖素材预览布局、深浅主题、玻璃/最大化还原、历史/设置复用、请求及轮询恢复、窗口关闭后的服务退出。工作台回归脚本完成 32 项检查。
- Python 90 项、前端状态 9 项、切镜初始化/瞬变/强切/静止/平移的 C++ 回归均通过。

上述为短样片和功能/精度验证，未进行 RTX 30/40 实机、长视频或 4K 长片 NR 性能对比。没有凭这些结果承诺普遍提速比例或主观画质提升。强度、尺寸和默认设置保持原有含义，VSR 仍未启用。测试输入、截图、日志与完整报告保存在仓库外隔离目录，未进入发行包或上传用户媒体。
